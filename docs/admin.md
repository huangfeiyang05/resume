# 管理后台第一阶段

管理网页位于 `/admin/`，通过同源 `/api/v1/admin/` 查询现有单进程 JSON 服务保存的业务记录。页面由独立构建产物提供，小程序不打包管理网页。

## 管理员登录

运维人员从已经过邮箱验证且设置密码的账号中明确选定管理员。账号本人可在普通登录后从 `GET /api/v1/auth/me` 响应的 `data.user.id` 查到账号 ID。服务端环境变量 `ADMIN_USER_IDS` 填写允许的账号 ID，多个 ID 用逗号分隔，留空关闭后台访问。授权按账号 ID 生效，修改服务端配置后需要重启服务。

管理员在后台输入邮箱和密码，服务端复用已有密码验证和登录限流。管理会话有效期一小时，使用独立的 HttpOnly、SameSite=Strict Cookie，生产环境要求 Secure。普通用户会话及小程序 Bearer 无法访问管理接口。退出管理后台会撤销当前管理会话，重置账号密码会撤销该账号的所有会话。

本地测试可以在启动 API 的终端设置 `ADMIN_USER_IDS` 为本地已验证账号 ID，再运行 `npm run dev:api`。另一个终端运行 `npm run dev:admin`，打开 `http://127.0.0.1:5174/admin/`。本地邮箱验证使用项目现有流程。线上管理员名单由运营者另行配置。

## 查询范围

- **运营概览**统计注册用户、滚动 7 天新增、当前有效会员、当前存留的失败诊断任务及待核对用量。点击异常卡片进入对应列表。
- **用户与会员**支持按完整邮箱、手机号或用户 ID 精确查询。响应只返回脱敏联系方式、绑定与验证状态、会员周期及最近权益变更类型、当前工作台权限和周额度摘要。
- **诊断与用量**支持按任务 ID、用户 ID、错误码精确查询，并按任务与用量状态筛选。响应包含任务状态、规则或模型来源、修订号、时间和用量状态。用户删除简历后，待核对用量仍可按任务 ID 定位。

两类查询按每页 20 条分页，查询条件放在 POST 请求体。登录与退出只变更会话，业务接口仅查询脱敏摘要。AI 未知用量沿用 [凭供应商证据进行线下核对的流程](ai-quota.md#未知用量的线下核对)。

下一阶段接入求职资料的草稿、校验、发布和回滚，并在首次开放内容写入时记录操作审计。订单及资金相关操作按支付和存储能力另行实施。
