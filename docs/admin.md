# 管理后台

管理网页位于 `/admin/`，通过同源 `/api/v1/admin/` 查询现有单进程 JSON 服务保存的业务记录。页面由独立构建产物提供，小程序不打包管理网页。

## 管理员登录

运维人员从已经过邮箱验证且设置密码的账号中明确选定管理员。账号本人可在普通登录后从 `GET /api/v1/auth/me` 响应的 `data.user.id` 查到账号 ID。服务端环境变量 `ADMIN_USER_IDS` 填写允许的账号 ID，多个 ID 用逗号分隔，留空关闭后台访问。授权按账号 ID 生效，修改服务端配置后需要重启服务。

管理员在后台输入邮箱和密码，服务端复用已有密码验证和登录限流。管理会话有效期一小时，使用独立的 HttpOnly、SameSite=Strict Cookie，生产环境要求 Secure。普通用户会话及小程序 Bearer 无法访问管理接口。退出管理后台会撤销当前管理会话，重置账号密码会撤销该账号的所有会话。

本地测试可以在启动 API 的终端设置 `ADMIN_USER_IDS` 为本地已验证账号 ID，再运行 `npm run dev:api`。另一个终端运行 `npm run dev:admin`，打开 `http://127.0.0.1:5174/admin/`。本地邮箱验证使用项目现有流程。线上管理员名单由运营者另行配置。

## 查询范围

- **运营概览**统计注册用户、滚动 7 天新增、当前有效会员、当前存留的失败诊断任务及待核对用量。点击异常卡片进入对应列表。
- **用户与会员**支持按完整邮箱、手机号或用户 ID 精确查询。已绑定邮箱和手机号在管理会话内分列完整显示，同时展示会员周期、工作台权限和周额度摘要。
- **支付订单**位于「用户与会员」。可按站内订单 ID、用户 ID 或商户订单号精确查找，并按支付状态、渠道筛选。用户列表中的「查看订单」限定为该账号。订单列表展示套餐、下单金额、支付状态、时间及对应的会员开通周期。
- **诊断与用量**支持按任务 ID、用户 ID、错误码精确查询，并按任务与用量状态筛选。响应包含任务状态、规则或模型来源、修订号、时间和用量状态。用户删除简历后，待核对用量仍可按任务 ID 定位。

列表查询按每页 20 条分页，查询条件放在 POST 请求体。AI 未知用量沿用 [凭供应商证据进行线下核对的流程](ai-quota.md#未知用量的线下核对)。

订单接口为 `POST /api/v1/admin/orders/search`，可选字段为 `query`、`userId`、`status`、`channel`、`page`。支付状态取自本站保存的订单。会员开通记录须匹配同一用户的支付事件、渠道、套餐和支付时间。已支付订单缺少匹配记录时显示「待核对」。商户订单号仅用作查询输入，响应也排除支付凭据和第三方流水号。

## 会员退款

在「用户与会员 → 支付订单」打开已支付订单的「退款」，核对原路全额退款金额、当前会员及退款成功后的变化，再勾选确认。退款金额取自原订单，后台保存发起管理员、退款单号、金额、状态和确认时间。

收到验签成功且金额匹配的渠道结果后，服务端撤销本单权益。其他已付款周期保留原日期。退续费会撤掉该次续费周期，退补差升级会撤掉本次追加的周期和该次升级带来的权限。处理中或待核对时继续按现有会员权益提供服务。

退款状态在订单列表查看。后台会短时复查，之后可点击「查询退款结果」。超时可通过「重试同一退款」按原退款单号核对和重试。入口需要已配置的原支付渠道和对应会员开通记录。实现与回退边界见 [支付与退款](payment.md#后台会员退款)。

## 会员价格

在左侧「会员价格」填写初级月价、高级月价和可选的高级首充价，按元输入并保留最多两位小数。首充价留空关闭优惠。先预览差异，再确认发布到页面标出的公开版或测试版。

发布会更新该环境的方案和新报价。已创建订单继续按原金额支付及退款。新客户端按用户确认的金额请求下单，报价变化时会重新显示金额。首次发布公开价格前，需让在用的小程序升级到支持该校验的版本。价格发布后，缺少确认金额的新下单请求会提示升级，原订单查询与重复请求仍走原金额。

价格历史记录版本、管理员和发布时间。可将历史价格填回表单，再预览并作为新版本发布。

## 测试版与公开版

在项目根目录运行 `npm run test-env` 启动独立本机测试环境。浏览器入口为 `http://127.0.0.1:5175/`，管理后台为 `http://127.0.0.1:5175/admin/`。首次启动会在私有 `.test-data/admin-login.json` 生成测试管理员登录信息。

可在该文件填写 `username` 及对应的 `password`，然后重启测试版。前台和后台均可用该账号登录，测试数据继续归属同一账号。

测试账号、Cookie、简历、价格版本、订单和退款都在测试环境内。用测试账号登录 H5 后，从「权益」进入会员方案并选「模拟支付」，随后可在测试后台验证退款及权益撤销。两个环境的后台分别发布各自价格。

建议用新账号验证首充、续费与升级差额，再以调价前后的订单验证锁价。用模拟退款检查只撤销本单、其他已付周期保留。把代码和价格在测试环境分别核对后，再在公开版走正常发布。

## 求职内容

1. 在「求职内容」选择「复习资料」或「招聘岗位」，选择现有条目或新建草稿。资料需要标题、专业、来源名称，以及正文或一个附件。PDF／Word（.docx）最大 10 MB，H.264 MP4 最大 30 MB。可另填简介和来源链接。岗位需要招聘单位、工作地点、任职要求、官方详情链接及核对日期。
2. 保存草稿后，点「预览发布」。左栏展示当前会员可见内容，右栏展示本次操作后的内容。服务端校验结构、日期、链接格式和目录容量。管理员核对来源归属、内容可读性及分享权限后勾选确认。发布时拒绝已经过期的预览。
3. 对已展示条目，可预览后下架。在操作历史中可预览、恢复以前发布的版本。后台首次编辑或下架时保存原目录条目的快照，便于恢复。下架与回滚保留尚未发布的草稿。
4. 每次成功写入记录操作、管理员用户 ID、时间和版本。回滚额外记录来源版本，并生成新的操作版本，保留原记录。重复提交同一操作复用原结果。

草稿只在管理员后台可见。上传成功后，可从草稿或对照预览下载检查文档，或直接播放视频。发布版本随高级会员工作台下一次读取生效。网页端可下载文档或在线播放视频，微信端下载到临时文件后打开文档或播放视频。替换、下架和回滚与资料版本联动，只有当前发布的附件可由高级会员请求。已完成上传的文件保留供版本恢复。

历史招聘入口及操作记录仍可从既有数据读取。岗位的当前投递状态以官方公告为准。请勿将用户简历、私人联系方式或密钥作为共享资料发布。

### 招聘岗位复核与发布

打开 **求职内容 → 招聘岗位 → 只看待复核岗位**，打开官方详情核对单位、城市、类型、届别、岗位条件、开放状态和截止日期。刷新核对日期后保存草稿，预览差异，确认发布。官方未给出截止日期时留空。官网已关闭的岗位可标记关闭并保留来源，或通过对照预览下架。超过 30 天未复核的开放稿须更新核对日期后才能发布。发布检查重复的岗位来源链接。

已有岗位沿用原 ID。发布、下架和回滚会同步影响岗位列表、助手和创建投递计划，已有投递快照保持当时的内容。后台操作保留独立历史与操作者。旧版本应用可读取数据库，回退期间会显示该旧版本随包岗位及其原先规则，后台岗位操作在恢复当前版本后重新生效。

列表和详情使用 `GET /api/v1/admin/career-content` 和 `GET /api/v1/admin/career-content/{kind}/{id}`。详情路径下的 `POST /draft`、`POST /preview`、`POST /apply` 分别用于保存、生成对照和确认。保存绑定修订标识，确认还绑定预览标识，写入携带独立操作 ID。管理会话和操作人均由服务端验证。

## 企业资料

在「企业资料」可选择上传 CSV／JSON、直接填写或修改已有记录。新增时填写企业名称和通用来源，核对预览后确认发布。上传和直接填写的预览可下载完整审核报告。

修改已有记录时，按企业名称或别名搜索，用招聘批次、届别、工作地点和来源区分同名记录。选择一条后填写修改依据，预览变更字段的前后差异，再确认修改。可回滚当前目录对应的最新后台操作。操作与数据边界见 [企业资料库](company-library.md#后台批量导入)。

修改接口使用 `POST /api/v1/admin/company-batches/records/search` 分页搜索，`GET /api/v1/admin/company-batches/records/{id}` 返回记录及目录修订，`POST /api/v1/admin/company-batches/edit-preview` 校验修订并生成对照，`POST /api/v1/admin/company-batches/apply` 确认发布。全部接口使用独立管理会话。
