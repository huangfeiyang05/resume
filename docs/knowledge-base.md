2026-10-27 按用户要求先推进功能与资料收集，以应届生为主覆盖现有 16 个专业。新增 [求职资料库](career-library/README.md)，将原创简历准备清单、官方来源复习提纲和招聘入口接入工作台供人阅读。该目录没有接入模型检索，不是 RAG；学习提纲不能转化为用户事实，招聘入口不能转化为未经核实的在招岗位。备案和个体工商户办理完成后再接入相关正式能力。

## 2026-11-13 已接入的原创岗位参考卡

服务端按目标岗位名称和 JD 词语，从 16 张原创专业卡中选至多一张。无明确方向或并列时不引用。规则报告保存所选卡、版本与本次输入并显示取证问题。百炼适配器将同一张卡作为生成上下文，并校验输出引用只能指向该卡，仍要求建议定位本人简历原文。当前线上规则模式可看到取证问题，真实生成只在单独配置并完成用户告知后运行。本次以模拟供应商验证输入、引用与保存流程。没有创建向量索引、云知识库或私人简历索引。

招聘岗位、企业历史资料、外部教学原件和用户上传的附件均不进入生成上下文。专业卡修改后递增源文件版本并重建产物。规则/无知识模型/有知识模型三组质量比较留给受控试用。

## 推荐分工

| 内容 | 推荐位置 | 原因 |
| --- | --- | --- |
| 用户、简历正文与修订、事实确认、任务、订单和额度 | 自己的业务数据库，未来 MySQL；当前仍是 `.data/` | 保持资源归属、事务、版本和幂等权威 |
| 经授权的岗位能力说明、行业术语、写作规范 | 初期试用百炼知识库，并自己保留原件与来源清单 | 减少自行开发文档解析、切分、索引、检索的工作 |
| 私人简历与用户附件 | 私有存储与业务库 | 不进入所有用户共享知识库；检索前必须完成用户隔离 |
| 知识来源、版本、授权范围、更新时间和文档 ID 映射 | 自己维护元数据清单，后续持久化 | 支持审计、撤回、重新索引及迁移供应商 |

普通数据库建表只完成内容存储；RAG 还需解析、切分、embedding 或其他检索索引、召回、排序、来源引用与权限过滤。MySQL 可以作为原始内容和元数据的权威存储，具体检索方案需另选，不能把建表等同于已实现 RAG。

## 初期接法

先整理少量有授权和出处的 Markdown / PDF 文档，按岗位与主题分类。百炼知识库可承担解析、切分和检索；本项目服务端检索后，把相关片段连同来源与版本交给现有模型 provider，输出保留引用。直接调用模型也可以使用此链路，不必先创建对话 Agent。模型不会因为控制台建了知识库就自动使用它，仍需要实现检索适配。

检索内容与简历均为不可信资料，不能覆盖系统指令；知识库讲的是岗位要求，不是用户真实经历，不能把召回内容直接写成用户事实。私人知识库必须服务端按用户或授权范围过滤，完成隔离测试再开启。具体平台过滤能力和费用需在选定知识服务后验证，当前没有接入。

当检索质量、跨供应商、复杂过滤或私有部署需求明确，再考虑自行维护向量检索层；前端领域接口无需绑定百炼 SDK。
