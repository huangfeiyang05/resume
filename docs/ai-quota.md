# AI 周额度与实际用量结算

2026-11-05 按用户确认的方案实现。额度按千问供应商实际计费的输入与输出 Token 管理，不使用固定点数或调用次数；即使本项目诊断失败，已经确认发生的模型用量仍计入用户额度。当前仍是单进程 JSON 业务地基，不是 MySQL 事务账本或多实例生产任务队列。

## 容量与页面

服务端 `server/quota-storage.ts` 的 `weeklyTokenLimits` 当前试运行配置为初级 `basic: 200_000`、高级 `premium: 800_000`。这些是后台容量，不是已验证的套餐成本或已售权益。

公共 `AiQuotaSummary` 只返回 `{status,remainingPercent,resetsAt,expiresAt,pending}`。有效会员显示整数剩余百分比和北京时间刷新时刻；百分比以已确认实际消耗计算并向上取整，正余额不会被舍入成 0%。不展示绝对 Token、单次消耗，也不在发送按钮标价或弹出扣减提示。预占只用于接单检查，不冒充实际扣减；有处理中或待核对记录时显示状态，百分比大于零也不能绕过在途限制。

无可信会员记录时为 `status: preview`，百分比和刷新/到期字段均为 `null`，保留现有演示体验，不伪造 100% 或付费身份。存在到期会员记录时为 `inactive`，保留实际到期时刻，新真实模型请求返回 `MEMBERSHIP_EXPIRED`；历史报告和本地规则继续可用。有效可信会员才显示 `active` 并执行对应周上限。

支付仍关闭。`POST /billing/checkout` 不授予会员；`QuotaService.activateMembership` 只供未来已验证支付适配器及受信测试使用，要求可信事件、用户、等级、确认时刻及幂等键，不存在用户可调用的 HTTP 发放接口。不能把内部调用或测试数据表述为已支付。

## 周期与会员变化

- 首次可信激活立即建立周额度，从该时刻起每 7 × 24 小时刷新，不按自然周周一重置，不结转。
- 连续续费只延长会员时间，保留周起点，不提前刷新。
- 有效初级升高级保留周起点、本周已用量和未结算预占，改用高级总容量；会员有效期在原到期日基础上顺延一个自然月，原剩余天数保留。
- 最后不足一周的额度窗口随会员到期结束。`resetsAt` 截断为 `expiresAt` 时，界面显示“本期额度有效至”，不承诺到期后刷新。
- 到期后重新购买建立新的周起点。跨周任务始终结算提交时的周期；旧周核对释放不增加新周余额。

自然月、上海时区和月末截断规则见 [会员机制](membership.md)。一个月可能涵盖五个额度窗口，不能把“一个自然月”等同固定四周。

## 预占、派发与结算

真实模型请求先保存任务和固定输入，再按完整输入的保守 Token 上界及最大输出预占；字节上界只用于预占，不作为最终扣减依据。余额不足以覆盖预占返回 `AI_QUOTA_EXHAUSTED`，不派发新调用。全服务保持单并发，每个用户最多一条未完成用量记录；本人仍有处理或未知用量时返回 `QUOTA_TASK_PENDING`。

| 记录状态 | 含义及处理 |
| --- | --- |
| `reserved` | 尚未派发的预占；调用前失败或取消可释放 |
| `dispatched` | 已持久化发送意图，可能已产生供应商用量 |
| `pending` | 已发送但没有有效实际用量，保留预占，等待可信证据核对 |
| `settled` | 已记录并结算供应商实际输入、输出和总 Token |
| `released` | 尚未发送，或已依据可信证据确认未计费，预占释放 |

适配器在模型输出内容校验之前读取 `usage.prompt_tokens / completion_tokens / total_tokens`。用量必须是非负安全整数，输入与输出之和等于总量；推理或缓存明细不再次相加。结构、来源、事实问题校验失败，简历版本冲突，报告保存失败，超时或取消，都不撤销已经确认的实际用量。一个请求发生新的真实模型调用时，该调用的新用量也计入额度。

没有派发则不扣；已经派发但没有有效 `usage` 时不能根据失败、超时、字数或“没看到结果”认定零用量。成功保存了报告也可能缺少用量，此时报告可查看，额度仍待核对。未知用量会阻止该用户的新模型调用，即使原周已结束也不能绕过核对；没有自动按估值扣减或定时免扣。

查看旧报告、确认应用、导出、规则检查及现有求职助手的本地资料查询不发起模型调用，不消耗 AI 周额度。

## 幂等与重启

诊断任务的 ID、输入快照、修订号、输入/请求 hash、模型与工作流版本及幂等键写入 `analysisTasks`。有效会员真实模型请求必须携带修订号和幂等键；客户端按账号保存状态不明的请求标识，重连复用或查询原任务。相同用户同键同输入返回原任务，同键不同输入拒绝；相同供应商请求用量不能重复关联或重复扣减。主动重新生成使用新任务，不把新的供应商用量当作重放免费处理。

进程重启保留任务 ID，将原 `queued / running` 标为 `failed`、`JOB_INTERRUPTED`，不重放模型调用。预占尚未发送时释放，已发送且未知用量转为 `pending`，已确认结算不重复扣减。任务和用量状态来自服务器持久化记录，不信任客户端提交的余额、会员身份或支付结果。

新增 `memberships / aiUsage / analysisTasks` 存在版本 3 的同一私有 JSON 中；旧文件缺失字段时补空，已有字段损坏时拒绝加载，不能静默当作没有额度记录。`.data/`、证据和备份不得进入 Git 或发布静态目录。

## 未知用量的线下核对

发布包提供 `ops/reconcile-ai-usage.sh` 和 `ops/reconcile-ai-usage.mjs`，源码在 `deploy/`。它们是管理员线下维护工具，不是 HTTP 接口，也不会自行调用供应商、启用模型、发放会员或验证支付。工具只验证证据结构、任务关联、幂等和状态；管理员仍须核实供应商账单或用量证据的真实性。仅有本地超时或错误码不能作为未计费证据。

证据文件只允许以下字段：

```json
{
  "userId": "USER_ID_FROM_LEDGER",
  "taskId": "TASK_ID_FROM_LEDGER",
  "idempotencyKey": "quota-reconcile-evidence-unique-id",
  "reason": "供应商用量核对依据的内部编号",
  "usage": {
    "inputTokens": 1000,
    "outputTokens": 500,
    "totalTokens": 1500,
    "requestId": "SUPPLIER_REQUEST_ID"
  }
}
```

上面的数字和标识仅为格式示例，不能直接用于线上结算。`requestId` 可选；其余 Token 字段须来自实际证据并且总量一致。若供应商证据确认没有计费用量，用 `"confirmedNoUsage": true` 替代整个 `usage` 对象，两者必须且只能提供其一。`reason` 最多 500 字，仅记核对依据编号，不能包含简历正文、手机号、邮箱、密钥或鉴权头。

同一个核对幂等键和相同证据可安全重放；同键不同证据、跨任务复用键、跨用户任务、已结算却试图以“未计费”撤销等请求被拒绝。核对事件持久化留痕。

只有获得可信证据且既有服务已经停止后才运行。证据大小不得超过 8 KB，必须为 root 属主的普通非符号链接文件，权限为 `0600` 或 `0400`。可先将私有审核文件安装到受限位置：

```sh
sudo install -m 0600 -o root -g root /受限审核目录/已核实证据.json /root/resume-quota-evidence.json
sudo bash /opt/resume-youfang/current/ops/reconcile-ai-usage.sh /root/resume-quota-evidence.json
```

命令不会自行停止或启动服务。包装脚本检查 root 身份、服务已加载且 `MainPID=0`、状态为 `inactive/failed`、数据路径与当前版本，取得现有部署锁，在 `/var/backups/resume-youfang/quota-reconcile-*` 创建 root 专属备份，然后以应用用户 `resume-youfang` 执行本地核对。不得绕过包装脚本让运行中的第二个 JSON 写进程同时修改数据。核对成功后由维护者按原服务流程恢复并校验；失败时保留备份和待核对状态，不自动释放或凭估值修改。

成功输出仅包含核对结果、任务标识、状态及备份目录；失败输出固定安全提示，不打印证据内容。证据、备份及包含用户标识的维护输出均应保留在受限位置，不提交 Git。本次代码发布只交付并验证工具，不执行线上核对、不制造线上用量或会员，不变更真实模型、支付和运行时业务配置。
