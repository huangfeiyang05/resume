# 求职诊断评测

使用 8 份完全合成的简历与 JD。样本覆盖软件、数据实习、工程、财会、供应链、教师资格、重复原文及不明确的岗位。期望条件、证据片段、岗位卡和优先修改目标保存在 [评测样本](../tests/fixtures/diagnosis-evaluation.ts)。规则基线命令如下。

```sh
npm run diagnosis:evaluate
```

脚本核对指定资格与任职条目的分类、证据是否定位到预期原文、专业卡是否正确选取、建议首条是否定位到需要处理的经历。每条可应用建议应定位唯一原文、保留原句并要求填写真实事实。自动校验无法判断模型文字中的所有暗示、事实推断或用户是否觉得有帮助。

已具备本地百炼配置时，经授权可用 `npm run diagnosis:evaluate -- --bailian` 比较同一组样本上的规则、百炼无卡与百炼带卡。两组模型使用同一设置，逐条串行，调用上限为 16 次，读取供应商实际用量，网络或鉴权等错误时停止后续模型请求。该命令读取本地服务端配置，使用固定合成数据，独立于用户账户、线上配置和会员额度。输出仅存入被忽略的 `.deployment/diagnosis-evaluation-*.json`，汇总会显示完成率、延迟、供应商用量及优先建议命中。三组的 JD 条件与原文定位都来自共享规则基线，比较模型增益应看各自生成的建议。

试用阶段可以给同一位求职者随机展示同一份简历和 JD 的两种结果。记录首个可用建议耗时、采纳建议条数与实际导出，审核每条建议是否引用真实原文、是否追问可验证证据、是否夸大技能或创造新事实。涉及本人简历时需获得当事人授权并先去标识。出现虚构成果、把缺失条件描述成已满足或引用其他人的信息，应先修正再开放对应功能。

网页与微信发布分别验收。已发布网页可检查公开入口、健康检查与未登录接口。微信需由项目账号确认审核状态，在真机逐项验收微信登录、文件导入、诊断、导出及已配置的支付与退款。账号注销请求、真实支付验收及备份恢复均单独记录。备份只在隔离目录验证可读取与恢复，正式库保持独立。
