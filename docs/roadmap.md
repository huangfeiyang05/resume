## 2026-11-08 求职内容管理

管理后台支持企业资料 CSV／JSON 批次预览、审核报告、确认追加和最新批次回滚。完全相同的记录跳过，同名且内容不同的记录独立保留。有待处理行时先修正原件。流程见 [企业资料库](company-library.md#后台批量导入)。

管理后台增加复习资料和官方招聘入口的草稿保存、对照校验、确认发布、下架、历史回滚与操作记录。后台确认绑定服务端修订和预览，按操作 ID 幂等处理。内容版本和审计在原 JSON 存储内原子提交，已发布条目随高级会员工作台下次读取生效。企业历史资料与具体共享岗位继续使用现有目录。使用说明见 [管理后台](admin.md)。

## 2026-11-07：新建简历弹窗导入正文

H5 的新建／编辑简历弹窗增加“上传 Word / PDF”，复用本机文件解析：支持 `.docx`、有文字层的 PDF、TXT 和 Markdown，文件最多 10 MB、PDF 最多 50 页、提取正文最多 50,000 字符。旧版 `.doc`、扫描件 OCR 和服务端原文件上传仍未接入；加密、损坏、空文件、超限及不可提取文字有明确提示。提取的是可编辑正文，不恢复原文件排版、不补写用户事实，也不自动调用模型。

导入绑定当前编辑会话与正文：为空或仍为默认填写骨架时直接填入，其余先预览、由用户确认替换；保留自定义简历名称和目标岗位，仅新建简历的默认／空名称可采用文件名。选择文件后的解析默认 30 秒超时，取消、超时、关闭编辑器或切换编辑会话后丢弃迟到结果；确认预览前正文又发生变化时也拒绝覆盖。解析及待确认期间阻止保存，先完成或取消导入，再保存。

原文件不上传，导入不消耗 AI 额度；填入正文只更新当前账号的本机草稿，用户核对后点击保存才同步服务端，后续继续分析、对照审核和确认应用。微信弹窗使用文本粘贴或“从剪贴板导入”，复用已有正文的替换确认和会话保护，但不引入浏览器文件解析或声称微信已支持 Word／PDF 上传。若选择“保存并诊断”，分析仍独立遵守原有真实模型告知与 Token 周额度。验收执行相关类型检查、行为测试及 H5、`mp-weixin`、服务端构建；按用户要求不做浏览器或截图验证，页面显示与微信真机另行验收。

## 2026-11-05：手机号验证码与同账号绑定

已接入腾讯云短信发送适配器、手机号验证码登录/未注册自动创建账号，以及同账号绑定手机号、邮箱的前后端流程。已绑定号码登录原账号；phone-only 账号不生成假邮箱和默认密码，绑定不改变账号 ID 或业务资料。绑定要求当前密码或已绑定手机 `verify-account` 验证码，加目标 `bind-phone / bind-email` 验证码；phone-only 绑定邮箱还须设置合规密码。冲突标识不能自动合并，没有改绑或解绑。

短信默认关闭；截图中的资质通过、关联签名为 0 不表示可发送。本轮尚缺用户确认的 SDKAppID、审核通过签名名和模板 ID，不采用聊天密钥、不更改服务器短信业务配置、不发真实短信。手机号入口按 `/auth/providers.phone` 显示真实状态；供应商确认提交不代表最终送达。默认验证码六位、5 分钟有效、60 秒冷却、5 次错误锁定，单号/IP/全局频率及2并发均在服务端限制，失败提交也计入限额，不自动重试。

## 2026-11-05：实际 Token 周额度与持久化诊断任务

用户确认初级、高级采用不同的每周 Token 容量，界面只显示剩余百分比和刷新时间，不展示点数、次数或单次扣减。当前后台试运行配置分别为 200,000、800,000 Token，每 7 天从首次可信激活时刻刷新；升级及连续续费保留周起点与已用量，会员到期拒绝新的模型请求。真实用量来自供应商输入加输出 Token，即使输出校验、保存、超时或取消失败，只要已取得有效实际用量就结算；未派发则释放，派发后未知则待核对并阻止该账号新模型调用。规则和历史报告等功能不扣模型额度。

诊断任务与输入快照、幂等键和用量账本现已使用单进程 JSON 持久化。重复请求复用原任务，重启保留任务 ID 并将未完成任务标为中断失败，不自动重放模型；未知用量不自动免扣。新增受部署锁、停服检查和受限备份保护的线下核对工具，只能凭可信供应商证据运行，本次发布不执行线上核对。

真实支付和默认模型开关保持原状态，没有新增 HTTP 会员授予入口、自动付款或假会员。无服务端会员记录仍是免费预览，不捏造 100% 或到期日；内部可信激活方法用于后续支付适配器和受信测试。当前不是 MySQL 或多实例生产任务队列。完整实现边界见 [AI 周额度](ai-quota.md)、[会员机制](membership.md) 和 [API 契约](api.md)。以下阶段记录中的相关任务与额度说明以本节及上述现行文档为准。

## 第一阶段：本轮基础工程

产品的第一步是让用户看清简历为什么缺少说服力：经历只有职责、成果没有证据、表达过于笼统、与目标岗位的关键词脱节。页面以清晰留白、低饱和背景、轻量卡片和显著主操作构成苹果风格，优先呈现问题、证据和下一步行动。

当前工程使用 uni-app / Vue 3 / TypeScript，H5 与微信小程序共享业务界面；Node API 使用本地 JSON 持久化。无模型密钥也可体验规则诊断。2026-10-11 增加本机百炼真实模型适配；诊断任务已于 2026-11-05 改为单进程持久化，需服务端启用配置及用户确认告知，参考分和关键词仍为规则。规则引擎返回评分维度、原文证据、具体建议与岗位关键词，不能声称它理解全部经历或给出真实招聘评分。

当前导航为“首页、工作台、权益、我的”四个底部入口。“工作台”直接进入求职界面，原“发现”中间页已移除。工作台概览中的两个说明框改为问答式求职助手，可选择本人已保存的简历并输入要求，通过本地规则查询历史企业资料和本人目标岗位；结果展示实际条件与文本依据，不构成当前在招或录用推荐。诊断操作绑定所选修订号，并进入现有对照审核与确认应用流程。首页集中完成简历选择/导入、目标岗位输入、可选 JD、诊断与报告查看；目标岗位独立于保存的简历，用于本次分析。首页只有一个“简历布局”区域，统一选择经典简约（黑白）、现代留白（浅蓝）、专业商务（深蓝）三种风格，提供版式预览、Word 模板下载和已保存正文的 Word / PDF 导出；“我的”负责简历管理。“权益”已按用户新机制调整为免费体验、初级会员、高级会员三档预览，替代单次、7 天、30 天档位。模板简历为基础权益；初级规划提供简历优化；高级包含初级权益及按专业的公司岗位信息、复习资料、精选投递（智能投递），工作台已提供岗位筛选、收藏、个人岗位添加、复习资料阅读和简历版本绑定的投递计划；首批原创资料及官方招聘入口已接入，具体在招岗位仍需按官方公告核实，实际代投未接入。支付尚未开放，不扣钱、不自动发放会员；无可信会员记录时保持现有预览体验，有有效记录时执行实际 Token 周额度。

会员月价待定，AI 已按实际 Token 周额度管理，不按次数固定扣减。初级有效期内升高级按两档月价补差，支付成功确认时立即升级并在原到期日基础上顺延一个自然月，原剩余时间保留；日期按 `Asia/Shanghai` 计算，月末无对应日期时截到次月月底。两档均不自动续费。规则及例子见 `membership.md`；日期计算与规则预览不代表已接入支付、订单或会员发放。

## 第二阶段：生产后端与微信基础接入

使用 Spring Boot 3 / Java 17 模块化单体承接领域：

| `auth` | 微信登录、可信会话、用户归属检查、注销与删除 |

| `ai` | 任务状态、固定输入、规则/模型 provider、结果校验、建议确认与应用 |

验收：跨用户访问被拒绝；同时编辑不会丢失更新；文件类型与大小校验通过；用户可删除自己的简历与文件；会话过期可恢复；真实微信身份来自服务端交换与校验；H5 与微信真机访问同一服务端通过。当前邮箱会话实现与命令行行为验证不能替代这些完整生产验收，页面实际效果按本轮用户要求自行检查。

## 第三阶段：真实 AI 与 RAG

先以服务端稳定的领域契约封装一个真实模型 provider。Spring AI 可承接 Java 主栈中的模型调用与检索；当确有多步编排、检查点或人工确认需求时，再通过独立 Python 服务引入 LangChain 或 LangGraph，避免同时维护多个重复工作流框架。

固定的处理链路为：输入快照 → 诊断/岗位分析 → 必要的授权资料检索 → 生成候选建议 → 输出结构与来源校验 → 事实风险标记 → 用户确认 → 事务保存新版本。私人简历必须按用户隔离检索；通用岗位知识与用户事实分开，知识材料不能被用于虚构用户经历。

RAG 的价值是引入有来源、可更新的岗位知识与写作规范，并保留引用，不是自动证明模型输出真实。先用一组去标识化样本比较规则基线与模型结果，再决定知识库、检索和工作流的复杂度。

验收：不编造单位/学历/日期/指标；缺失信息变为待补充问题；输出引用可追溯；分析结果绑定固定版本与输入 hash；错误结构不能应用；旧建议被拒绝；同一供应商用量与重复请求不重复结算，重新调用产生的新用量计入额度，未知用量待核对；预算与并发限制可观测。上线时准确标注实际 provider 和能力，取消演示规则的 AI 暗示。

## 第四阶段：导出、权益与商业闭环

在现有服务端按需导出基础上补齐版本绑定的短期下载权限后，再按 `membership.md` 接入初级、高级会员与广告解锁；不再沿用原方案的单次、7 天、30 天商品。两档月价、额度容量的持续评估和平台支付规则需基于当前官方要求与真实成本另行确认，原始方案仅作产品假设。高级会员的资料与精选投递还需真实内容来源、用户授权、任务状态和失败路径，不能用预览按钮代替服务。

支付以服务端验签通知和核单为准；广告以可信验证能力为准；额度采用账本，当前为单进程原子文件写入，生产迁移后使用数据库事务。AI 按供应商实际用量结算，已派发但未知的用量保留待核对，未派发才直接释放预占；下载失败不重复消耗已经授予的权限。前端无权声明已支付、已看完广告、已成为会员或有剩余额度。

验收：重复回调不会重复发放；并发请求不超扣；同一任务的失败、重试和成功有唯一结算；退款有对应权益调整；广告无填充或未完成有明确出口；下载权限过期与版本变化可解释。升级须核对服务端当前等级、有效期和商品价格，有效初级才能补差，过期按高级新购；升级从原到期日顺延一个自然月并保留剩余时间，同档续费保留已购有效期，月末与闰年规则有行为测试；失败或重复支付通知不能产生额外有效期。

## 第五阶段：受控上线

小规模真实用户测试前完成隐私告知、模型处理告知、日志脱敏、文件私有权限、删除与注销、成本上限、备份恢复和失败告警。生产环境使用独立密钥、数据库与存储，不复用本地测试数据。

用户已授权本项目后续代码更新在通过相关检查后同步 `huangfeiyang05/resume` 与既有服务器，沿用受限备份、新发布目录和发布校验；超出既有发布范围的生产资源、真实支付或平台能力接入仍需相应条件和授权。用户当轮要求只本地修改、只审查或不部署时遵从该轮要求。公网恢复、页面效果和微信真机分别验收，不能由推送或构建成功代替。上线评估优先看创建完成率、可理解且可采纳的建议比例、事实风险、失败恢复、导出成功率和服务成本。公司岗位资料、复习资料和精选投递按高级会员规划分阶段接入，并分别验收内容来源、专业分类、用户授权和实际执行结果；面试模拟或复杂多 Agent 工作流另行评估。

本机模型接入配置、告知与任务边界见 README 和 `api.md`；知识库选型见 `knowledge-base.md`。Spring AI、MySQL 迁移和生产任务服务仍为后续计划。
