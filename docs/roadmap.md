# 开发路线与验收边界

本文件将原始产品方案与当前交付分开。原方案见 `product-source.md`；初期目标是在本地完成可运行、可检查、便于替换后端的产品地基，不承诺原方案所有能力已实现，也不沿用其中未验证的价格与排期。当前同步与部署范围以用户最新授权和下方记录为准。

## 当前推进顺序（2026-10-27）

用户明确要求先完成项目功能和资料收集。资料以应届生为主，覆盖现有 16 个专业方向；备案和个体工商户申请由用户继续办理，完成后再接入相应正式能力，不作为功能开发的等待条件。2026-10-27 完成本地功能与资料批次后，用户进一步要求部署当前版本并上传 `huangfeiyang05/resume`，后续代码更新同步 Git 和既有服务器；该要求取代此前该开发批次“本轮不部署”的限制。相关流程见 `deployment.md`，部署结果以实际校验为准，不能据此宣称备案完成或公网恢复。

当前交付重点：

1. 简历创建、编辑与建议应用保留不可变历史版本；用户对照当前和历史正文、确认后恢复为新版本。强制修改携带修订号，恢复有幂等保护，旧数据只从当前已知版本开始记录。
2. 将原有 16 个原创专业简历提示卡接入工作台，再补齐各专业应届生复习提纲与可核查的官方招聘入口，提供专业筛选、正文阅读、来源和日期。
3. 招聘入口与具体岗位分开展示；仅核验到入口时不生成“在招岗位”，用户核对真实公告后可录入个人目标岗位，再贯穿分析、审核与投递计划。

后续功能按用户链路继续收口：诊断任务持久化与请求幂等、事实补充后的受约束改写与质量评估、双端文件导入、资料维护工具和完整删除/注销。MySQL 与 Spring Boot 按领域迁移，避免一次性重写阻塞可用功能。真实支付、广告、微信身份等依赖主体资质与平台配置的接入在条件齐备后另行实施；当前不虚构会员身份、支付结果或实际代投。

验收仍使用类型检查、行为测试和 H5 / mp-weixin / 服务端构建；不进行浏览器、截图或显示效果验证，微信真机另行验收。

2026-10-25 增加经用户授权的服务器部署及邮箱账号接入，详见 `deployment.md` 和 `api.md`：H5 登录/注册页面取代浏览器共享密码弹窗，服务端会话保护业务 API，并按会话用户隔离简历、报告、诊断任务和建议应用。H5 使用 HttpOnly Cookie，小程序邮箱登录预留 Bearer 传输方式；微信免登与手机号验证登录尚未接入，不展示为已可用能力。服务器数据独立于本机，默认关闭真实模型，仍使用单进程 JSON，而非 MySQL 或完整生产后端。

按用户要求，验收保留类型检查、行为测试和构建，不再执行浏览器、截图或显示效果验证；页面实际效果由用户自行验收。微信真机仍需单独验证。

本轮继续接入 SMTP 邮箱验证码注册、已有账号邮箱验证和密码找回。邮件挑战与账号会话保存在版本 3 的单进程 JSON 中；验证码单次使用、过期、重发和错误次数由服务端控制，找回成功撤销旧会话且不自动登录。旧未验证账号须先凭原密码登录并验证邮箱，找回流程不用于认领旧资料。SMTP 认证与提交结果不能代替最终收件验收，邮件配置只保留在受限的服务端环境中。

## 第一阶段：本轮基础工程

产品的第一步是让用户看清简历为什么缺少说服力：经历只有职责、成果没有证据、表达过于笼统、与目标岗位的关键词脱节。页面以清晰留白、低饱和背景、轻量卡片和显著主操作构成苹果风格，优先呈现问题、证据和下一步行动。

当前工程使用 uni-app / Vue 3 / TypeScript，H5 与微信小程序共享业务界面；Node API 使用本地 JSON 持久化。无模型密钥也可体验规则诊断。2026-10-11 增加本机百炼真实模型适配与内存诊断任务，需服务端启用配置及用户确认告知，参考分和关键词仍为规则。规则引擎返回评分维度、原文证据、具体建议与岗位关键词，不能声称它理解全部经历或给出真实招聘评分。

当前导航为“首页、发现、权益、我的”四个底部入口。首页集中完成简历选择/导入、目标岗位输入、可选 JD、诊断与报告查看；目标岗位独立于保存的简历，用于本次分析。首页只有一个“简历布局”区域，“发现”定位到同一区域，统一选择经典简约（黑白）、现代留白（浅蓝）、专业商务（深蓝）三种风格，提供版式预览、Word 模板下载和已保存正文的 Word / PDF 导出；“我的”负责简历管理。“权益”已按用户新机制调整为免费体验、初级会员、高级会员三档预览，替代单次、7 天、30 天档位。模板简历为基础权益；初级规划提供简历优化；高级包含初级权益及按专业的公司岗位信息、复习资料、精选投递（智能投递），工作台已提供岗位筛选、收藏、个人岗位添加、复习资料阅读和简历版本绑定的投递计划；首批原创资料及官方招聘入口已接入，具体在招岗位仍需按官方公告核实，实际代投未接入。支付尚未开放，不扣费、不发放会员，现有体验不执行套餐限制。

会员价格与次数待定。初级有效期内升高级按两档月价补差，支付成功确认时立即升级并重置一个自然月，原剩余时间不叠加；日期按 `Asia/Shanghai` 计算，月末无对应日期时截到次月月底。两档均不自动续费。规则及例子见 `membership.md`；日期计算与规则预览不代表已接入支付、订单或会员发放。

## 第二阶段：生产后端与微信基础接入

使用 Spring Boot 3 / Java 17 模块化单体承接领域：

| 领域 | 首批职责 |
| --- | --- |
| `auth` | 微信登录、可信会话、用户归属检查、注销与删除 |
| `resume` | 简历与不可变版本、上传校验、私有文件存储、解析任务 |
| `ai` | 任务状态、固定输入、规则/模型 provider、结果校验、建议确认与应用 |
| `export` | 模板渲染、PDF 任务、私有下载、失败恢复 |
| `membership` | 权益检查、原子预占、成功结算、失败释放 |
| `billing` | 商品、订单、支付通知验签、主动核单、退款与幂等发放 |

以 `data-model.sql` 为生产设计起点，将本地 JSON 数据结构映射到正式迁移后再启用数据库；不能直接将设计稿视为已验证迁移。沿用本轮邮箱会话、用户归属检查、版本冲突和幂等的行为契约，再补齐数据库事务、真实微信免登与账号绑定、手机号验证、持久队列与生产运维，并将现有邮件验证码和账号找回迁移到事务及生产任务边界。微信云托管和私有存储的具体配置需在目标环境实现与验证。

验收：跨用户访问被拒绝；同时编辑不会丢失更新；文件类型与大小校验通过；用户可删除自己的简历与文件；会话过期可恢复；真实微信身份来自服务端交换与校验；H5 与微信真机访问同一服务端通过。当前邮箱会话实现与命令行行为验证不能替代这些完整生产验收，页面实际效果按本轮用户要求自行检查。

## 第三阶段：真实 AI 与 RAG

先以服务端稳定的领域契约封装一个真实模型 provider。Spring AI 可承接 Java 主栈中的模型调用与检索；当确有多步编排、检查点或人工确认需求时，再通过独立 Python 服务引入 LangChain 或 LangGraph，避免同时维护多个重复工作流框架。

固定的处理链路为：输入快照 → 诊断/岗位分析 → 必要的授权资料检索 → 生成候选建议 → 输出结构与来源校验 → 事实风险标记 → 用户确认 → 事务保存新版本。私人简历必须按用户隔离检索；通用岗位知识与用户事实分开，知识材料不能被用于虚构用户经历。

RAG 的价值是引入有来源、可更新的岗位知识与写作规范，并保留引用，不是自动证明模型输出真实。先用一组去标识化样本比较规则基线与模型结果，再决定知识库、检索和工作流的复杂度。

验收：不编造单位/学历/日期/指标；缺失信息变为待补充问题；输出引用可追溯；分析结果绑定固定版本与输入 hash；错误结构不能应用；旧建议被拒绝；超时、取消、重试和重复请求不会重复扣次；预算与并发限制可观测。上线时准确标注实际 provider 和能力，取消演示规则的 AI 暗示。

## 第四阶段：导出、权益与商业闭环

在现有服务端按需导出基础上补齐版本绑定的短期下载权限后，再按 `membership.md` 接入初级、高级会员与广告解锁；不再沿用原方案的单次、7 天、30 天商品。两档月价、次数和平台支付规则需基于当前官方要求与真实成本另行确认，原始方案仅作产品假设。高级会员的资料与精选投递还需真实内容来源、用户授权、任务状态和失败路径，不能用预览按钮代替服务。

支付以服务端验签通知和核单为准；广告以可信验证能力为准；额度使用账本与事务。AI 失败释放预占，下载失败不重复消耗已经授予的权限。前端无权声明已支付、已看完广告、已成为会员或有剩余额度。

验收：重复回调不会重复发放；并发请求不超扣；同一任务的失败、重试和成功有唯一结算；退款有对应权益调整；广告无填充或未完成有明确出口；下载权限过期与版本变化可解释。升级须核对服务端当前等级、有效期和商品价格，有效初级才能补差，过期按高级新购；升级从确认支付成功的时刻重置一个自然月，同档续费保留已购有效期，月末与闰年规则有行为测试；失败或重复支付通知不能产生额外有效期。

## 第五阶段：受控上线

小规模真实用户测试前完成隐私告知、模型处理告知、日志脱敏、文件私有权限、删除与注销、成本上限、备份恢复和失败告警。生产环境使用独立密钥、数据库与存储，不复用本地测试数据。

用户已授权本项目后续代码更新在通过相关检查后同步 `huangfeiyang05/resume` 与既有服务器，沿用受限备份、新发布目录和发布校验；超出既有发布范围的生产资源、真实支付或平台能力接入仍需相应条件和授权。用户当轮要求只本地修改、只审查或不部署时遵从该轮要求。公网恢复、页面效果和微信真机分别验收，不能由推送或构建成功代替。上线评估优先看创建完成率、可理解且可采纳的建议比例、事实风险、失败恢复、导出成功率和服务成本。公司岗位资料、复习资料和精选投递按高级会员规划分阶段接入，并分别验收内容来源、专业分类、用户授权和实际执行结果；面试模拟或复杂多 Agent 工作流另行评估。

本机模型接入配置、告知与任务边界见 README 和 `api.md`；知识库选型见 `knowledge-base.md`。Spring AI、MySQL 迁移和生产任务服务仍为后续计划。
