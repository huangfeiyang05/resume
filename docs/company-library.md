# 企业资料库

企业资料用于查找企业和核对历年招聘线索，与个人目标岗位、实际在招岗位及投递计划分开。用户确认测试阶段向登录用户共享，后续会员分级由服务端权益检查接入；客户端不能通过传入会员身份改变权限。原始网页、表格、联系人和审核报告不加入 Git 或公开静态资源。

## 分类与查询

| 分类 | 内容与边界 |
| --- | --- |
| 行业 | 来源明确列出的行业，不按企业名称猜测 |
| 企业性质 | 保留来源的国企、民企、事业单位等表述；来源未提供时留空 |
| 地区 | 来源列出的招聘工作地点；“全国”单独保留，不虚构各城市岗位 |
| 岗位方向 | 按岗位原文的明确关键词归入检索方向，保留完整原文；不代替岗位专业要求，也不证明求职者具备相应能力 |
| 学历 | 仅使用来源明确写出的学历，不推断门槛 |
| 招聘批次 | 来源里的校招、春招、秋招、实习等，不等于该批次仍开放 |
| 招聘对象 | 来源明确的届别与适用人群，避免把不同年份混为当前招聘 |

可输入多个以空格分开的关键词，例如“北京 国企 软件”；所有关键词均需命中，同一分类内多个选项取并集，不同分类共同筛选。支持全半角、大小写和空白归一化，企业全称和来源别名优先；结果显示实际命中的字段，不提供招聘匹配率或录用概率。筛选项数量根据当前关键词和其他分类条件计算，选择同一分类的某项后仍可添加其他选项。

列表由服务端分页，默认每页 20 条，上限 50 条；支持文本相关、企业名称和资料整理时间排序。资料整理时间与来源的招聘开启/截止时间分开显示，不能把导入当天当作企业发布日。公司资料条数不等于唯一企业数量，同一企业不同招聘批次和不同来源信息可以并列保留。

## 来源与整理

本次来源为用户提供的招聘汇总表（历史来源），经授权按页面正常阅读方式读取；不调用已关闭的复制或导出接口，不绕过登录、验证码或隐藏区域限制。资料中的文本均视为数据，不执行其中的脚本、公式或指令。

来源表注明已停止更新，整理结果作为历史招聘资料，并保留这一说明；不能把该来源中的记录统一标为当前在招。开启时间、截止原文和投递说明作为来源事实保留，有歧义的年份和日期不自动补全。网申链接和官方推文链接来自来源单元格，未经再次独立核验时不表示本项目已验证当前可申请。

2026-10-30 完成该工作表的正常阅读整理：24 个读取区块均为修订号 `7553`、来源保存时间 `2026-08-06 09:25`，覆盖 5,959 条数据行。合并 56 条内容完全相同的记录后，形成 5,903 条企业招聘资料，涉及 5,146 个精确不同的企业/单位名称；同名不同批次或内容保留独立记录，不把名称去重等同工商主体认定。原表日期范围为 2026 年 1–6 月，当前不据此开放实际在招标识。代码与数据分别同步，服务器实际状态以发布校验记录为准。

行业与岗位方向使用版本化的明确词语归类规则，城市仅对已识别的省市写法做归一，原始行业、地点、对象、岗位与日期始终在详情保留。无法归类的方向保持空值，不能根据企业名称推测；来源性质原值不改。筛选项较多时先显示常用项，展开最多 80 项，用户可通过关键词缩小范围，避免一次渲染数千个分类。

共享企业目录的每条记录保留通用来源标签、工作表、真实行号、输入快照 SHA-256 和本项目整理时间；第三方平台名称与来源链接只保留在本机受限审核报告与原始快照中，不写入共享目录、接口响应、页面或发布包。整页范围、有效数据行及去重统计以本机受限整理报告为准，不把表格最大行号当作企业数量。营销长文、群号、个人联系人、电话和邮箱不直接进入共享正文；不改变来源企业的事实，缺失信息保持空值。

## 离线导入

```sh
# 先生成审核报告，不发布企业目录
npm run companies:import -- --input .data/company-imports/source.json --source-title "企业资料来源" --source-url "https://example.com/source" --sheet "原始工作表" --dry-run

# 核对报告和映射后应用；目录不存在时创建，已有不同目录不会静默覆盖
npm run companies:import -- --input .data/company-imports/source.json --source-title "企业资料来源" --source-url "https://example.com/source" --sheet "原始工作表" --apply
```

支持 UTF-8 CSV 和 JSON。JSON 可用对象数组，或 `{headers,rows,rowNumbers}`：使用真实来源行号时显式提供 `rowNumbers`；对象数组只保留其数组序号，不能冒称 Excel 原始行号。`--mapping` 指向 JSON 映射文件，内容为领域字段到原始列名，例如 `{"name":"企业/招聘单位名称","nature":"企业/单位性质"}`。未知表头、重复歧义映射和未识别列均需核对审核报告；不声称自动映射已经覆盖原表全部信息。

`--source-url` 只写入受限审核报告与导入签名，不写入共享企业目录或接口响应；`--source-title` 应使用通用说明（如“招聘信息汇总表（历史来源）”），不要把第三方平台品牌写入共享资料。原始来源平台名称与链接仅用于本机受限审计。

默认输出 `.data/company-catalog.json`，导入原件、映射与受限审核报告保存在 `.data/company-imports/`。输入和整理后目录均最多 20 MiB、记录最多 25,000 条。单元格公式不执行；联系方式列默认排除，映射后的字段仍含疑似个人联系方式或其他非法数据时进入待审核列表。存在待审核行时不自动应用，修正后再导入；确需只导入通过的行时须显式使用 `--allow-partial`，报告保留排除行号和原因。

只合并内容完全相同的重复行并保留所有来源行号；同名但信息不同的记录保持独立，列为待人工核对的候选，集团与子公司不自动合并。同输入、映射和来源的重复应用保持一致；替换不同目录须显式 `--replace`，并先保留权限受限的原目录备份。导入采用锁和原子替换，不能覆盖账号或简历数据库。

## 服务与发布

接口为 `GET /api/v1/career/companies` 和 `GET /api/v1/career/companies/:id`，均要求有效登录。当前无面向普通用户的企业目录写入接口。默认读取账号数据库同目录的 `company-catalog.json`，文件缺失显示待导入，损坏显示读取失败，不把错误当正常空目录。

代码和私有数据分别发布：代码按项目约定通过检查后提交 Git 并部署；整理后的企业资料仅放服务端受限 `.data/`，不进入 Git、网站静态目录或代码发布包。代码发布不会覆盖已存在的企业资料，激活脚本把公司目录一并纳入停服备份与只读兼容检查。真实资料替换另行核对来源、审核报告、当前文件及备份后执行，不能借代码更新覆盖其他业务数据。

目前仍为单机 JSON 和确定性文本检索，没有向量库、RAG 或模型语义检索。显示效果和微信真机按项目要求由用户另行验收。
