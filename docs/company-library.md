# 企业资料库

企业资料用于查找企业和核对历年招聘线索，与个人目标岗位、实际在招岗位及投递计划分开。测试阶段曾向登录用户共享；2026-11-07 起，企业列表、详情及求职助手查询均要求服务端有效高级会员权限，取代此前共享预览安排。客户端不能通过传入会员身份改变权限，界面锁态来自 `/api/v1/membership/workbench`。原始网页、表格、联系人和审核报告不加入 Git 或公开静态资源。

## 分类与查询

| 分类 | 内容与边界 |
| --- | --- |
| 行业 | 来源明确列出的行业，不按企业名称猜测 |
| 企业性质 | 保留来源的国企、民企、事业单位等表述；来源未提供时留空 |
| 地区 | 来源列出的招聘工作地点；“全国”单独保留，不虚构各城市岗位 |
| 岗位方向 | 按岗位原文的明确关键词归入检索方向，保留完整原文；不代替岗位专业要求，也不证明求职者具备相应能力 |
| 学历 | 仅使用来源明确写出的学历，不推断门槛 |
| 招聘批次 | 来源里的校招、春招、秋招、实习等，不等于该批次仍开放 |
| 招聘对象 | 来源明确的届别与适用人群，避免把不同年份混为当前招聘 |

可输入多个以空格分开的关键词，例如“北京 国企 软件”；所有关键词均需命中，同一分类内多个选项取并集，不同分类共同筛选。支持全半角、大小写和空白归一化，企业全称和来源别名优先；结果显示实际命中的字段，不提供招聘匹配率或录用概率。筛选项数量根据当前关键词和其他分类条件计算，选择同一分类的某项后仍可添加其他选项。

列表由服务端分页，默认每页 20 条，上限 50 条；支持文本相关、企业名称和资料整理时间排序。资料整理时间不逐条展示，只用于排序和内部核对；详情只保留来源的网申截止时间原文，不再逐条展示来源状态、来源开启/更新日期等来源元信息，不能把导入当天当作企业发布日。公司资料条数不等于唯一企业数量，同一企业不同招聘批次和不同来源信息可以并列保留。

## 来源与整理

本次来源为用户提供的招聘汇总表（历史来源），经授权按页面正常阅读方式读取；不调用已关闭的复制或导出接口，不绕过登录、验证码或隐藏区域限制。资料中的文本均视为数据，不执行其中的脚本、公式或指令。

来源表注明已停止更新，整理结果作为历史招聘资料，不能把该来源中的记录统一标为当前在招。网申截止原文和投递说明作为来源事实保留；来源状态与来源开启/更新日期只保留在本机受限整理报告，不在共享资料中逐条展示。有歧义的年份和日期不自动补全。网申链接和官方推文链接来自来源单元格，未经再次独立核验时不表示本项目已验证当前可申请。

2026-10-30 完成该工作表的正常阅读整理：24 个读取区块均为修订号 `7553`、来源保存时间 `2026-08-06 09:25`，覆盖 5,959 条数据行。合并 58 条内容完全相同的记录后，形成 5,901 条企业招聘资料，涉及 5,146 个精确不同的企业/单位名称；其中 2 对记录原本仅相差“来源开启/更新日期”，该日期不再进入共享资料后内容一致而合并。同名不同批次或内容保留独立记录，不把名称去重等同工商主体认定。原表日期范围为 2026 年 1–6 月，当前不据此开放实际在招标识。代码与数据分别同步，服务器实际状态以发布校验记录为准。

行业与岗位方向使用版本化的明确词语归类规则，城市仅对已识别的省市写法做归一，含“不含、以外、除外”等排除条件的地点保留原文，原始行业、地点、对象、岗位与网申截止原文始终在详情保留。无法归类的方向保持空值，不能根据企业名称推测；来源性质原值不改。筛选项较多时先显示常用项，展开最多 80 项，用户可通过关键词缩小范围，避免一次渲染数千个分类。

共享企业目录的每条记录保留通用来源标签、工作表、真实行号、输入快照 SHA-256 和本项目整理时间（仅用于排序与内部核对，不在页面逐条展示）；第三方平台名称与来源链接只保留在本机受限审核报告与原始快照中，不写入共享目录、接口响应、页面或发布包。整页范围、有效数据行及去重统计以本机受限整理报告为准，不把表格最大行号当作企业数量。营销长文、群号、个人联系人、电话和邮箱不直接进入共享正文；链接中的编码联系方式、联系人查询参数或片段也会排除，数字职位编号不直接视为电话；不改变来源企业的事实，缺失信息保持空值。

## 后台批量导入

少量资料可以在「企业资料 → 录入方式」选择「直接填写」，一次录入一条。企业名称和通用来源名称必填，行业、地点、招聘批次、链接等按来源填写。点击「预览填写内容」核对整理后的字段，再确认发布。直接填写与上传表格共用查重、待处理行校验、发布记录和回滚。

管理员可从「企业资料」上传不超过 10 MB 的 UTF-8 CSV 或 JSON，填写通用来源名称，可选工作表、CSV 表头行和字段映射。后台沿用离线导入的行校验和联系方式排除规则。审核报告提供新增、库内重复、同名差异和待处理行，报告只包含整理后的字段与行号。待处理行阻止本批发布，修正原件后重新上传。

确认发布会追加新记录，内容完全相同的记录跳过。不同批次或同名且内容不同的记录独立保留。发布后高级会员下次查询读取新目录。招聘链接继续作为历史参考来源，官方招聘入口仍单独审核发布。

已发布记录可在「录入方式」选择「修改已有记录」，搜索名称或别名并选中要更正的一条。填写通用修改依据，列表字段每行填写一项，核对变化字段的前后差异再确认。修改保留原记录 ID、原始导入来源和未编辑字段，修改依据与记录 ID 记入发布历史。目录变化后须重新选择并预览。修改后若与其他记录完全相同，或重新导入时与已修改记录的旧标识冲突，需先核对后再发布。

可预览并回滚当前目录对应的最新后台操作。回滚单条修改时，对照会列出恢复前后的字段。目录在预览后发生变化会要求重新审核。操作历史记录管理员、时间、来源摘要和前后版本。目录与离线导入共用写入锁。服务端在 `.data/company-batches/` 保存受限历史和目录快照，发布部署一并备份。预览与审核报告在当前进程最多保留 20 分钟。

## 离线导入

```sh
# 先生成审核报告，不发布企业目录
npm run companies:import -- --input .data/company-imports/source.json --source-title "企业资料来源" --source-url "https://example.com/source" --sheet "原始工作表" --dry-run

# 核对报告和映射后应用；目录不存在时创建，已有不同目录不会静默覆盖
npm run companies:import -- --input .data/company-imports/source.json --source-title "企业资料来源" --source-url "https://example.com/source" --sheet "原始工作表" --apply
```

支持 UTF-8 CSV 和 JSON。JSON 可用对象数组，或 `{headers,rows,rowNumbers}`：使用真实来源行号时显式提供 `rowNumbers`；对象数组只保留其数组序号，不能冒称 Excel 原始行号。`--mapping` 指向 JSON 映射文件，内容为领域字段到原始列名，例如 `{"name":"企业/招聘单位名称","nature":"企业/单位性质"}`。未知表头、重复歧义映射和未识别列均需核对审核报告；不声称自动映射已经覆盖原表全部信息。

`--source-url` 只写入受限审核报告与导入签名，不写入共享企业目录或接口响应；`--source-title` 应使用通用说明（如“招聘信息汇总表（历史来源）”），不要把第三方平台品牌写入共享资料。原始来源平台名称与链接仅用于本机受限审计。

默认输出 `.data/company-catalog.json`，导入原件、映射与受限审核报告保存在 `.data/company-imports/`。输入和整理后目录均最多 20 MiB、记录最多 25,000 条。单元格公式不执行；联系方式列默认排除，映射后的字段仍含疑似个人联系方式或其他非法数据时进入待审核列表。存在待审核行时不自动应用，修正后再导入；确需只导入通过的行时须显式使用 `--allow-partial`，报告保留排除行号和原因。

只合并内容完全相同的重复行并保留所有来源行号；同名但信息不同的记录保持独立，列为待人工核对的候选，集团与子公司不自动合并。同输入、映射和来源的重复应用保持一致；替换不同目录须显式 `--replace`，并先保留权限受限的原目录备份。导入采用锁和原子替换，不能覆盖账号或简历数据库。

## 服务与发布

接口为 `GET /api/v1/career/companies` 和 `GET /api/v1/career/companies/:id`，均要求有效会话及高级会员的 `companyJobs` 权限；求职助手的企业检索也先检查 `careerAssistant` 权限。权限不足返回 403 `WORKBENCH_MEMBERSHIP_REQUIRED`，不返回企业正文、链接或筛选计数。列表的 `access: authenticated-test` 保留为兼容标签，不再表示向所有登录账号开放，不能用于判断权限。非高级的 `/career` 数据数组为空；权限记录读取失败返回 503 `WORKBENCH_ACCESS_UNAVAILABLE`，界面提供重试，不提示用户因网络错误升级。

当前无面向普通用户的企业目录写入接口。授权查询默认读取账号数据库同目录的 `company-catalog.json`，文件缺失显示待导入，损坏显示读取失败，不把错误当正常空目录。会员控制不改变来源事实、目录文件及资料核验边界，详见 [工作台权限](membership.md#工作台锁态与权限2026-11-07) 与 [API 契约](api.md)。

代码和私有数据分别发布：代码按项目约定通过检查后提交 Git 并部署；整理后的企业资料仅放服务端受限 `.data/`，不进入 Git、网站静态目录或代码发布包。代码发布不会覆盖已存在的企业资料，激活脚本把公司目录一并纳入停服备份与只读兼容检查。真实资料替换另行核对来源、审核报告、当前文件及备份后执行，不能借代码更新覆盖其他业务数据。

目前仍为单机 JSON 和确定性文本检索，没有向量库、RAG 或模型语义检索。显示效果和微信真机按项目要求由用户另行验收。
