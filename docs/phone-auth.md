# 手机号验证码与同账号绑定

## 微信手机号实时验证

小程序「我的 → 账号登录方式」支持主动授权微信手机号。此能力单独配置，认证的非个人主体须在微信后台开通手机号实时验证，并在小程序用户隐私保护指引声明手机号用途。设置 WECHAT_PHONE_ENABLED=true 后才开放入口，短信验证码能力继续由 SMS_ENABLED 控制。微信手机号授权不发送本项目短信。参见 [微信手机号实时验证组件](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/getRealtimePhoneNumber.html)。

服务端用新的微信登录 code 核对当前账号 OpenID，再用独立手机号授权 code 换取微信验证号码，校验 AppID、时间和中国大陆号码格式。绑定保留原用户 ID、简历及会员。已属于其他账号的号码返回冲突。微信账号在小程序绑定邮箱时，也可用新的微信登录 code 核对本人，再验证目标邮箱并设置密码，适用于未启用短信的环境。

小程序按用户选择保存头像和昵称，微信侧隐私指引需声明头像及昵称。昵称可自主填写，头像 JPG 或 PNG 按本人账号鉴权读取，可随时替换或移除。网页端使用同一账号资料。本机头像位于 .data/account-avatars，随代码发布前的受限备份保存。

## 短信验证码

2026-11-05 接入手机号验证码登录/注册及手机号、邮箱绑定。本节记录腾讯云短信验证码流程。代码就绪不代表已经可以向手机发送短信：本轮尚无用户确认的短信 SDKAppID、审核通过的签名名称和模板 ID，默认 `SMS_ENABLED=false`。本次发布不修改服务器短信业务配置，不使用聊天中发送的密钥，不发送真实短信。

## 上线前需要什么

用户提供的截图显示短信资质“已通过”，但“关联签名个数”为 0。这只证明截图中的资质状态，不能证明已有可用签名、模板、应用与发送权限，也不能据此声称短信已开通。需要在腾讯云控制台确认实际短信应用 SDKAppID，以及审核通过、适用于该应用和验证码用途的签名、模板，并准备权限受限的服务端凭据和可用短信余额/套餐。发送参数与响应字段以 [腾讯云 SendSms 官方接口](https://cloud.tencent.com/document/api/382/55981) 为准。

当前适配器向 `https://sms.tencentcloudapi.com/` 发送 `SendSms` 请求，使用 TC3-HMAC-SHA256 签名。每次只发送一个大陆号码，转成 `+86` 格式；`TemplateParamSet` 只有一个验证码变量，因此审核模板须与这个变量个数和位置匹配。有效期由应用固定为 5 分钟，模板中若展示有效期，应与此一致；不能在代码或文档中编造“已审核通过”的签名或模板。

所有配置仅保存在受限服务端环境中，不使用 `VITE_` 前缀，不进入仓库、前端包、发布静态目录、日志或截图。可参考 `.env.example` 的默认关闭结构：

```ini
SMS_ENABLED=false
SMS_PROVIDER=tencent
TENCENT_SMS_SECRET_ID=
TENCENT_SMS_SECRET_KEY=
TENCENT_SMS_SDK_APP_ID=
TENCENT_SMS_SIGN_NAME=
TENCENT_SMS_TEMPLATE_ID=
TENCENT_SMS_REGION=ap-guangzhou
TENCENT_SMS_TOKEN=
SMS_CODE_SECRET=
SMS_DAILY_LIMIT=100
```

`TENCENT_SMS_TOKEN` 仅在使用临时凭据时填写；其余身份、应用、签名和模板值须由真实配置提供。`SMS_CODE_SECRET` 为独立生成的至少 32 字节随机密钥，用于挑战 HMAC，不能复用腾讯云 SecretKey、SMTP 或模型密钥。更换后旧挑战需要重新获取。已关闭时不发请求、不假报成功；启用但必要配置不完整时拒绝启动，避免显示可用却无法发送。

配置由维护者在独立授权和真实材料齐备后填入 `/etc/resume-youfang/runtime.env`（权限 `0600`）并重启。不能把一次普通代码发布当作启用短信或修改此文件的授权。启用后仍需用户授权真实号码进行接收验收；供应商确认提交不代表最终送达手机。

## 登录与注册

登录页保留原邮箱登录、验证码注册与找回密码，同时增加“手机验证码”入口。未配置短信时入口明确显示暂未开放，发码与提交按钮不可用；服务端 `/auth/providers.phone` 才是实际启用依据。

手机号登录使用六位短信验证码，不要求预先设置密码。服务端验证成功后：

- 号码已绑定账号：登录原账号，保留原 `userId`、简历、报告、会员和其他资料。
- 号码未绑定账号：在同一次单进程持久化中消费验证码并创建手机号账号，再签发会话。
- 不生成占位邮箱、虚构邮箱验证状态或默认密码。公开 `AuthUser` 的 `email`、`phone` 可选，手机号账号有 `phoneVerified:true` 和 `hasPassword:false`；只有邮箱证明完成后才标记 `emailVerified:true`。

现有邮箱账号的用户应先用邮箱登录，再在“我的 → 账号登录方式”绑定手机号。若先用未绑定的新号码注册，会创建另一个独立账号；系统不会按相似资料、姓名或客户端声明自动合并。

H5 继续使用 HttpOnly、SameSite=Lax、生产环境 Secure Cookie；小程序继续使用不透明 Bearer 令牌，业务资源仍以可信会话的 `userId` 判断归属。验证码、手机表单和当前密码只保留在组件内存中，不写前端本地存储；小程序持久化的仅为会话令牌及有效期。

## 绑定两种登录方式

绑定要求已登录会话、当前账号身份证明，以及目标号码/邮箱验证码：

- 已有密码的账号：提供 `currentPassword` 证明当前身份。
- 仅有手机号、没有密码的账号：使用已绑定手机号的 `verify-account` 挑战，提供 `currentCode / currentChallengeId`。
- 绑定新手机号：再验证目标手机号的 `bind-phone` 挑战。
- 绑定新邮箱：再验证目标邮箱的 `bind-email` 挑战；手机号账号还须设置符合现有 6–16 位规则的新密码，之后才能通过邮箱和密码登录。

绑定后保留同一个账号 ID 与业务数据。目标标识若已属于另一个账号，明确拒绝，不搬移简历、不合并会员。重复绑定当前本人已绑定标识可返回已有状态，但不能据此改绑。当前没有手机号/邮箱直接替换、解绑、账号合并或号码回收后的自动认领功能；手机号在简历正文中出现也不构成登录或绑定证明。

验证码绑定目标、用途、随机挑战 ID；绑定与当前手机证明还绑定会话用户。登录码不能用于绑定，目标邮箱注册/找回码不能用于 `bind-email`，其他用户的挑战不能用于本账号。身份校验失败、绑定冲突或供应商失败不能显示为绑定成功。

## API

以下路径均以前缀 `/api/v1` 为准：

| 方法与路径 | 输入与边界 |
| --- | --- |
| `GET /auth/providers` | `phone:boolean` 来自服务端短信配置；不根据前端按钮或截图判断 |
| `POST /auth/phone/code` | `{phone,purpose}`；用途 `login / bind-phone / verify-account`，后两者需会话；`verify-account` 仅当前账号已绑定手机号 |
| `POST /auth/phone` | `{phone,code,challengeId}`；验证码登录，未注册则创建；返回与邮箱登录相同的会话 |
| `POST /auth/phone/bind` | `{phone,code,challengeId,currentPassword?}` 或携带 `currentCode/currentChallengeId`；需会话 |
| `POST /auth/email/code` | 原用途之外增加 `purpose:'bind-email'`；此用途需会话 |
| `POST /auth/email/bind` | `{email,code,challengeId,currentPassword?}` 或当前手机证明；无密码账号另需 `password`；需会话 |

发码成功响应为 `202` 和 `{challengeId,expiresAt,resendAfterSeconds,message}`，不返回验证码。绑定返回更新后的公开 `AuthUser`，不返回密码哈希或原始会话令牌。客户端仅在服务器确认后更新账号，拒绝其他账号 ID 或不一致标识的响应。

## 验证码与费用控制

验证码由安全随机数生成，六位数字，有效期 5 分钟。发码先持久化 `pending` 预占，供应商确认提交后才改为 `sent`；失败保留失败状态，验证码不可消费。成功重新发送同目标、用途和用户的验证码后，旧码失效。挑战只保存 HMAC，明文验证码只短暂传给发送适配器，不写数据库、API 响应或日志。

默认限制如下，各时间窗口均为滚动窗口：

| 范围 | 限制 |
| --- | --- |
| 同一手机号 | 至少间隔 60 秒；每小时 5 条、24 小时 10 条 |
| 同一客户端/IP 标签 | 每小时 10 条、24 小时 30 条 |
| 全服务 | `SMS_DAILY_LIMIT=100`，24 小时最多 100 次发送预占 |
| 在途发送 | 最多 2 个并发 |
| 单个挑战 | 最多 5 次错误，达到后锁定；过期或消费后不可复用 |

失败提交同样计入预占和发送限额，避免通过重复失败绕过成本控制。供应商请求有超时和响应大小上限，不自动重试；本地超时或连接中断不证明供应商没有计费。客户端倒计时以成功响应的 `resendAfterSeconds` 为准，失败不制造成功挑战或虚假倒计时。换号码、换用途、关闭表单和切换账号会清除旧证明；晚到的响应不能恢复旧验证码。

## 数据兼容与验收

`phoneChallenges` 增量保存在既有版本 3 的 `.data/resumes.json`，旧文件缺失时补空；既有邮箱账号、会话、简历、会员及微信绑定不迁移到新账号。手机、验证码挑战、凭据和备份均为私有数据，受现有 `.data/`、`.env*`、`.deployment/` 忽略规则保护，不进入 Git 或发布包。

只有手机号的账号不满足旧版“必须有邮箱和密码哈希”的假设，因此已有手机号账号后，旧程序可能无法读取数据。回退前必须用拟回退程序只读验证当前数据兼容性；数据文件不随代码回退，不用旧备份覆盖上线后产生的新账号或简历。

行为测试使用注入的假短信/邮件发送器，覆盖消费、过期、错误锁定、并发与频率限制、用途及用户隔离、绑定冲突、旧邮箱兼容和两种登录方式访问同一资料。它们不发送真实短信。交付另执行类型检查、H5、微信小程序和服务端构建；按用户要求不执行浏览器、截图或显示效果检查，手机短信实际收件与微信真机仍需另行验收。
