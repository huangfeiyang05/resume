# 求职工作台

## 问答入口

底部“工作台”直接进入求职界面。概览保留统计和分区入口，原流程说明及资料提示两个框由求职助手取代。助手允许选择本人已保存的简历、填写城市和岗位等要求并继续问答；用确定性规则筛选企业历史招聘资料、近期核对过来源的具体岗位及本人已录入的目标岗位，展示查询条件和简历文本依据。未提供简历也可按明确要求查询。当前标明本地规则模式，不能称为真实大模型或完整语义检索。

企业资料只作历史参考，薪资、当前在招状态和录用可能性均不能由已有资料推断。结果可预填个人岗位的企业名称，实际岗位和 JD 需核对后保存；本人岗位可带入首页对照分析。要求调整简历时，用户点击诊断操作才读取最新简历并校验所选修订号，再进入原诊断与逐项确认应用流程。过期动作无法覆盖新版本，未保存草稿保留。对话按账号保存在本机（H5 在浏览器本地缓存，小程序在本地缓存），发送后自动保存，可查看、切换、删除或新建；最多保留 12 段、每段最近 30 条消息。切换简历或要求会开始新对话，清理本机缓存后历史销毁；对话不上传服务端，也不写入共享企业库。

## 访问与操作

2026-11-07 按用户要求，工作台由登录账号共享预览改为按会员等级控制。历史预览安排不再作为免费使用依据。当前权限如下：

| 工作台入口 | 免费 | 初级 | 高级 |
| --- | --- | --- | --- |
| 简历优化 | 锁态，提示升级初级 | 可用 | 可用 |
| 求职助手、公司岗位、复习资料、投递计划 | 锁态，提示升级高级 | 锁态，提示升级高级 | 可用 |

受限入口使用浅雾化预览和锁标识，点击说明所需等级，并可前往“权益”查看方案。权限来自 `GET /api/v1/membership/workbench`，服务端按可信会话及当前有效的会员记录返回 `WorkbenchAccess`；无记录、未生效和到期均为免费权限。读取失败提供重试，不将网络或存储错误作为升级理由。界面不以额度百分比、客户端套餐选择或前端支付结果判断会员。

非高级的 `GET /api/v1/career` 返回空岗位、收藏、资料及投递记录数组。原 `portals` 字段固定返回空数组，以兼容已安装客户端。企业列表、详情、助手和受限写入均另外检查服务端权限，不足时返回 403 `WORKBENCH_MEMBERSHIP_REQUIRED`；查看权限本身失败返回 503 `WORKBENCH_ACCESS_UNAVAILABLE`。本人旧岗位与投递记录的删除接口继续检查归属和原有版本条件，不要求有效高级会员；本轮没有新增非高级查看旧岗位或计划的界面。本机历史对话另可清理。

首页及“我的”的简历创建、编辑、历史报告、规则检查、建议审核与确认应用、基础模板和导出继续可用。工作台的简历优化入口复用原有分析流程，不为免费首页规则检查新增会员限制，也不启用新的真实模型或支付配置。真实模型仍以服务端配置、用户告知及原有 Token 周额度为准。

现有 32 份面向应届生的原创准备材料覆盖 16 个专业。管理后台可维护复习资料和具体岗位。

## 用户操作

从底部“工作台”或“权益 → 体验主要功能”直接进入。

1. 在“公司岗位”搜索公司、岗位或地点，按专业和招聘类型筛选。打开岗位详情可复制官方来源链接。来源超过 30 天未复核的岗位仍可查原公告，核对后可录为个人目标岗位再建立计划。
2. 没有目录数据也可以添加自己找到的岗位。个人岗位仅本人可见，可填写公司、岗位、专业、地点、职位描述及可选来源、公司介绍与截止日期。
3. 将岗位要求带入现有简历分析流程。规则模式仍只检查表达、结构与文本关键词覆盖，建议经审核、事实确认后才能应用。
4. 选择已保存的简历版本，检查岗位与简历正文后建立投递计划。服务端保存当时的岗位及简历快照、简历修订号和内容哈希。
5. 自行完成真实投递后，明确确认“已自行完成投递”再记录状态。继续记录面试、录用、拒绝或撤回及备注。这些是用户记录的进度，系统没有联系公司或代发简历。

计划中的简历修改后，需要重新绑定并审核最新已保存版本，才能记录已投递。记录为已投递后，历史简历快照不再更换。删除原简历会一并删除绑定的投递记录与快照；删除投递记录须核对修订号。

在“复习资料”可按专业或岗位关键词查阅原创简历准备清单与复习提纲，阅读来源和本项目整理日期；没有将资料自动写进用户简历或接入 RAG。

## 内容维护

底稿优先来自与账号数据库同目录的 `career-catalog.json`，默认路径为 `.data/career-catalog.json`。该文件不存在时使用 `server/assets/career/catalog.json` 中的公开原创资料。自定义目录完整替换打包目录。测试可通过 `createApiServer` 的 `careerCatalogPath` 显式指定临时文件，此时缺失文件的底稿为空目录。

管理后台将已发布版本按类型和 ID 应用到当前底稿。后台发布、下架及回滚只影响相应条目，草稿保存在账号库的 `careerContent` 字段，由管理员单独读取。具体共享岗位也支持后台草稿、复核、发布、下架和回滚。岗位编辑记录单独保存在账号库的 `careerJobContent` 字段，既有个人岗位和投递数据继续按账号隔离。编辑流程见 [管理后台说明](admin.md)。

初始格式见 [空目录示例](career-catalog.example.json)：

```json
{ "version": 2, "jobs": [], "materials": [], "portals": [] }
```

旧 `version: 1`（不含 `portals`）继续支持并归一化为空入口数组。共享契约由 `shared/types.ts` 导出的 `CareerJob`、`CareerMaterial` 和 `CareerRecruitmentPortal` 定义。首批公开资料的来源、适用范围、版权边界和离线构建方式见 [求职资料库](career-library/README.md)。后续私人内容仍只存受限目录，不能放入公开资料包。

岗位字段：

| 字段 | 内容 |
| --- | --- |
| `id` / `origin` | 稳定且唯一的标识，目录岗位的 `origin` 为 `catalog` |
| `company` / `title` | 公司名称、岗位名称 |
| `major` / `location` | 专业分类、工作地点 |
| `description` / `companyOverview` | 职位要求及公司介绍，纯文本 |
| `sourceLabel` / `sourceUrl` | 资料来源名称与可选来源网址 |
| `deadline` | 可选截止日期，`YYYY-MM-DD`，以北京时间当日结束为界 |
| `availability` | `open` 或 `closed`；关闭或过期岗位不能新建计划或记录新投递 |
| `updatedAt` | 带时区的 ISO 更新时间 |

复习资料字段包括 `id`、`title`、`major`、`role`、`summary`、`content`、`sourceLabel`、可选 `sourceUrl`、`updatedAt` 和可选 `attachment`。纯文本正文直接阅读，PDF／Word（.docx）可下载，MP4 可在资料页播放。附件原件保存在私有目录，服务端按会话、有效高级会员与当前发布版本校验每次读取。网页端支持视频按字节范围读取，微信端通过带鉴权的临时下载播放，离开资料页会取消读取并清理播放器。附件按文件类型校验和限长。

历史招聘入口及其发布记录保留在底稿和账号库中。材料 `updatedAt` 表示本项目整理时间，来源机构的发布日期在核查记录中另行说明。

内容应有可核对的来源和日期。公司岗位资料、复习材料不应混入私人简历、联系方式或密钥。`.data/` 已被忽略，不能提交私人内容、备份和用户记录。

显式指定的目录缺失时显示“等待补充”；默认目录缺失时可使用打包资料。目录为空或损坏时不静默回退，格式损坏显示读取失败并保留个人岗位及投递记录，不把损坏文件伪装为空目录成功。不会伪造公司或岗位填满页面。

## 数据与业务边界

个人岗位、收藏、投递计划、简历快照和状态记录与账号数据库共同持久化，以可信会话的用户标识隔离。当前仍为单进程 JSON；新增字段兼容旧版本数据，不代表已经迁移到 MySQL。

应用创建使用幂等键，重复请求的同一键携带不同输入会冲突；状态和备注更新使用修订号。同一状态不会重复新增历史事件，终态不能回退，计划不能直接跳为录用。并发修改、跨账号读写、陈旧简历、事实占位内容和过期岗位均在服务端处理。

后续实际投递需单独确定渠道、用户授权和可验证结果。现有用户手动状态用于记录本人操作。

验收采用类型检查、行为测试、H5 与微信构建，不执行浏览器、截图或显示效果验证；微信真机由用户另行验收。代码与随包资料按 [既有发布流程](deployment.md) 同步，不变更服务器运行时密钥和业务配置。
