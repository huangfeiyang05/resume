# 求职工作台

工作台处于会员功能预览，已登录账号可体验，不将免费账号显示为已开通高级会员，不收费、不发放会员或虚构剩余额度。2026-10-27 按用户要求先推进功能和资料，首批提供面向应届生、覆盖 16 个专业的 32 份原创准备材料和 8 个官方招聘入口；内容管理后台另做。备案与主体申请完成后再接入相关正式能力，本轮不部署。

## 用户操作

从“发现 → 高级会员求职工作台”或“权益 → 体验主要功能”进入。

1. 在“招聘入口”按专业与机构筛选官方渠道，复制链接自行查阅最新公告。入口不表示有具体在招岗位；当前不创建未经核实的共享岗位记录。
2. 没有目录数据也可以添加自己找到的岗位。个人岗位仅本人可见，可填写公司、岗位、专业、地点、职位描述及可选来源、公司介绍与截止日期。
3. 将岗位要求带入现有简历分析流程。规则模式仍只检查表达、结构与文本关键词覆盖，建议经审核、事实确认后才能应用。
4. 选择已保存的简历版本，检查岗位与简历正文后建立投递计划。服务端保存当时的岗位及简历快照、简历修订号和内容哈希。
5. 自行完成真实投递后，明确确认“已自行完成投递”再记录状态。继续记录面试、录用、拒绝或撤回及备注。这些是用户记录的进度，系统没有联系公司或代发简历。

计划中的简历修改后，需要重新绑定并审核最新已保存版本，才能记录已投递。记录为已投递后，历史简历快照不再更换。删除原简历会一并删除绑定的投递记录与快照；删除投递记录须核对修订号。

在“复习资料”可按专业或岗位关键词查阅原创简历准备清单与复习提纲，阅读来源和本项目整理日期；没有将资料自动写进用户简历或接入 RAG。

## 内容维护

服务器优先从与账号数据库同一目录下的 `career-catalog.json` 读取内容。默认账号数据库位于 `.data/resumes.json`，对应目录文件即 `.data/career-catalog.json`；该默认文件不存在时使用 `server/assets/career/catalog.json` 中的公开原创资料。自定义目录完整替换打包目录，不自动合并。测试可通过 `createApiServer` 的 `careerCatalogPath` 显式指定临时文件，此时缺失文件仍返回空目录；没有面向用户的目录写入、上传或管理接口。

初始格式见 [空目录示例](career-catalog.example.json)：

```json
{ "version": 2, "jobs": [], "materials": [], "portals": [] }
```

旧 `version: 1`（不含 `portals`）继续支持并归一化为空入口数组。共享契约由 `shared/types.ts` 导出的 `CareerJob`、`CareerMaterial` 和 `CareerRecruitmentPortal` 定义。首批公开资料的来源、适用范围、版权边界和离线构建方式见 [求职资料库](career-library/README.md)。后续私人内容仍只存受限目录，不能放入公开资料包。

岗位字段：

| 字段 | 内容 |
| --- | --- |
| `id` / `origin` | 稳定且唯一的标识，目录岗位的 `origin` 为 `catalog` |
| `company` / `title` | 公司名称、岗位名称 |
| `major` / `location` | 专业分类、工作地点 |
| `description` / `companyOverview` | 职位要求及公司介绍，纯文本 |
| `sourceLabel` / `sourceUrl` | 资料来源名称与可选来源网址 |
| `deadline` | 可选截止日期，`YYYY-MM-DD`，以北京时间当日结束为界 |
| `availability` | `open` 或 `closed`；关闭或过期岗位不能新建计划或记录新投递 |
| `updatedAt` | 带时区的 ISO 更新时间 |

复习资料字段：`id`、`title`、`major`、`role`、`summary`、`content`、`sourceLabel`、可选 `sourceUrl`、`updatedAt`。本轮支持资料目录筛选和正文阅读，`content` 按纯文本展示，不执行指令，不渲染上传的 HTML。PDF、Word 等原文件的上传、解析、私有存储和下载以后另接。

招聘入口字段为 `id`、`organization`、`majors`、`audience`、`description`、HTTPS `sourceUrl` 和 `checkedAt`。专业标签只用于发现入口，不代表机构接受该专业；核查日期不是招聘排期。材料 `updatedAt` 表示本项目整理时间，来源机构的发布日期在核查记录中另行说明。

内容应有可核对的来源和日期。公司岗位资料、复习材料不应混入私人简历、联系方式或密钥。`.data/` 已被忽略，不能提交私人内容、备份和用户记录。

显式指定的目录缺失时显示“等待补充”；默认目录缺失时可使用打包资料。目录为空或损坏时不静默回退，格式损坏显示读取失败并保留个人岗位及投递记录，不把损坏文件伪装为空目录成功。不会伪造公司或岗位填满页面。

## 数据与业务边界

个人岗位、收藏、投递计划、简历快照和状态记录与账号数据库共同持久化，以可信会话的用户标识隔离。当前仍为单进程 JSON；新增字段兼容旧版本数据，不代表已经迁移到 MySQL。

应用创建使用幂等键，重复请求的同一键携带不同输入会冲突；状态和备注更新使用修订号。同一状态不会重复新增历史事件，终态不能回退，计划不能直接跳为录用。并发修改、跨账号读写、陈旧简历、事实占位内容和过期岗位均在服务端处理。

本轮不含管理页面、真实会员授权发放、支付、自动代投、企业招聘接口、招聘反馈同步、短信或邮件通知。后续实际投递需单独确定渠道、用户授权和可验证结果；现有用户手动状态不能当作招聘方回执。

验收采用类型检查、行为测试、H5 与微信构建，不执行浏览器、截图或显示效果验证；微信真机由用户另行验收。本轮不部署，不改生产资源。
